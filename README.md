# رفع نظام فرز السير الذاتية أونلاين (مجانًا)

الملفات في الفولدر ده:

| الملف | بيعمل إيه |
|---|---|
| `index.html` | البرنامج نفسه (ده اللي بيترفع على الإنترنت) |
| `config.js` | بيانات مشروعك (هتعدّل فيه سطرين بس) |
| `supabase/schema.sql` | بيبني قاعدة البيانات وقواعد الأمان (بتشغّله مرة في Supabase) |
| `supabase/functions/admin-api/index.ts` | الدالة اللي بتعمل الشركات والمستخدمين وكلمات السر (بتنسخها في Supabase) |

الوقت المتوقع: **30–40 دقيقة** أول مرة. كله مجاني.

---

## الخطوة 1 — إنشاء مشروع Supabase
1. ادخل على **supabase.com** واعمل حساب (يفضّل بإيميل مخصص للشغل، وفعّل التحقق بخطوتين على الحساب ده).
2. **New project**: اسمه أي حاجة (مثلًا `cv-screener`)، واختار **كلمة سر قوية لقاعدة البيانات** واحفظها، واختار أقرب Region ليك.
3. استنى دقيقتين لحد ما المشروع يجهز.

## الخطوة 2 — بناء قاعدة البيانات
1. من القايمة الجانبية: **SQL Editor ← New query**.
2. افتح `supabase/schema.sql` وانسخ **كل** محتواه والصقه ← **Run**.
3. لازم تشوف `Success`. (تقدر تشغّله تاني بدون أي ضرر.)

## الخطوة 3 — قفل التسجيل العشوائي (مهم للأمان)
**Authentication ← Sign In / Providers** (أو Settings) ← أوقف **Allow new users to sign up** ← Save.
ده يمنع أي حد من الإنترنت يعمل حساب لنفسه. الحسابات بتتعمل من جوه البرنامج بس.

## الخطوة 4 — إنشاء حسابك كمدير رئيسي
1. **Authentication ← Users ← Add user ← Create new user**.
   اكتب إيميلك وكلمة سر قوية (6 أحرف على الأقل، والأفضل 12+)، وفعّل **Auto Confirm User**.
2. ارجع **SQL Editor** وشغّل السطرين دول (بدّل الإيميل بإيميلك):
```sql
insert into public.profiles (id, role, username, name)
select id, 'super', 'owner', 'المدير الرئيسي' from auth.users where email = 'YOUR_EMAIL_HERE';
```
بتدخل البرنامج بعد كده بـ **الإيميل وكلمة السر دول** (وكود الشركة فاضي).

## الخطوة 5 — رفع الدالة (Edge Function)
1. **Edge Functions ← Deploy a new function ← Via Editor**.
2. الاسم بالظبط: `admin-api`
3. امسح الكود اللي موجود والصق محتوى `supabase/functions/admin-api/index.ts` ← **Deploy**.
4. افتح إعدادات الدالة (Function settings / Details) وأوقف خيار **Verify JWT** (أو "Verify JWT with legacy secret") ← Save.
   مش خطر: الدالة نفسها بتتحقق من هوية اللي بيناديها وصلاحيته قبل أي حاجة.
   (لو بتستخدم الـ CLI: `supabase functions deploy admin-api --no-verify-jwt`.)

## الخطوة 6 — ربط البرنامج بمشروعك
1. **Project Settings ← API** (أو API Keys): انسخ **Project URL** و **Publishable key** (بيبدأ بـ `sb_publishable_`، أو **anon** في الشكل القديم).
2. افتح `config.js` في النوتباد وحط القيمتين مكان `YOUR-PROJECT-ID` و `PASTE_PUBLISHABLE_KEY_HERE` ← احفظ.
   ⚠ **ماتحطش أبدًا** مفتاح `secret` أو `service_role`.

## الخطوة 7 — رفع الموقع (واحدة من الاتنين)
**Netlify (الأسهل):** ادخل **app.netlify.com/drop** وسحب فولدر فيه `index.html` و `config.js` بس. هيدّيك رابط فورًا.
**Cloudflare Pages:** Workers & Pages ← Create ← Pages ← Upload assets ← ارفع نفس الملفين.
الاتنين مجانيين وبيدّوك HTTPS تلقائيًا. تقدر تربط دومين خاص بيك بعدين.

## الخطوة 8 — أول تشغيل
1. افتح الرابط ← كود الشركة **فاضي** ← الإيميل ← كلمة السر.
2. صفحة **الشركات** ← أضف أول شركة (بيتولّد لها كود، وبتحدد اسم وكلمة سر لأدمنها).
3. سلّم الكود واليوزر وكلمة السر لأدمن الشركة. هو يعمل مستخدميه بنفسه.

## نقل بياناتك الحالية (من النسخة الأوف لاين)
في النسخة الأوف لاين: ادخل الشركة ← **الإعدادات ← تحميل النسخة الاحتياطية** (لكل شركة لوحدها).
في الأونلاين: ادخل الشركة نفسها ← **الإعدادات ← استرجاع نسخة** وارفع الملف. بيضيف الوظايف والسير والملفات الأصلية.

---

## مهم تعرفه

**الأمان**
- كلمات السر عند Supabase مش في الصفحة ولا في الكود، ومحدش (حتى إنت) يقدر يقراها.
- عزل الشركات بيتم **جوه قاعدة البيانات نفسها** (Row Level Security): حتى لو حد فتح F12 وحاول يبعت طلبات بإيده، القاعدة بترفض أي بيانات مش بتاعته. نفس الشيء لملفات السير.
- المفتاح اللي في `config.js` عام بطبيعته ومش خطر. المفتاح السري بيفضل جوه Supabase بس.

**الحدود المجانية (حسب المصادر وقت التجهيز — راجع صفحة الأسعار)**
- قاعدة بيانات حوالي 500MB، وتخزين ملفات حوالي 1GB.
- المشروع المجاني **بيتوقف لو ما اتستخدمش أسبوع**. حل مجاني: على **cron-job.org** اعمل مهمة يومية `POST` على
  `https://YOUR-PROJECT-ID.supabase.co/rest/v1/rpc/company_id_by_code`
  ومعاها Headers: `apikey: <المفتاح العام>` و `Content-Type: application/json`، والـ Body: `{"p_code":"ping"}`.
- لما الشغل يكبر: ترقية Supabase Pro (حوالي 25 دولار/شهر).
- نصوص السير بتتخزن في قاعدة البيانات (حوالي 5–10KB للسيرة)، والملفات الأصلية في التخزين. اضبط «الحد الأقصى للسير» لكل شركة من صفحة الشركات.

**الاستخدام**
- كلمات السر **6 أحرف على الأقل** (شرط Supabase).
- مفيش مزامنة لحظية بين المستخدمين: البيانات بتتحدّث لما ترجع للتبويب بعد 3 دقايق، أو بزرار ⟳ في الأعلى. لو اتنين عدّلوا نفس المرشح، آخر حفظ هو اللي بيفضل.
- بتحمّل كل سير الشركة عند الدخول (بدون النصوص الكاملة)؛ ده مريح لحد آلاف السير، وبعد كده نحتاج تقسيم للصفحات.
- نسيان كلمة السر: أدمن الشركة يعمل لمستخدمه كلمة جديدة من صفحة المستخدمين. وأنت تعمل لأدمن أي شركة. وكلمة سرك أنت تتغيّر من Supabase (Authentication ← Users).

**لو حصلت مشكلة**
- شاشة «إعداد غير مكتمل» ← `config.js` لسه فيه القيم الافتراضية.
- «بيانات الدخول غلط» لمستخدم شركة ← اتأكد من الكود، والمستخدم بيتكتب بنفس الشكل اللي اتسجل به (الحروف الكبيرة والصغيرة مش فارقة).
- خطأ عند إنشاء شركة/مستخدم ← الدالة `admin-api` ما اترفعتش باسمها الصحيح أو Verify JWT لسه شغّال.
- خطأ إيميل مرفوض عند إنشاء مستخدم ← غيّر الدومين: في Edge Functions ← Secrets ضيف `EMAIL_DOMAIN` بدومين ثاني، وحط نفس القيمة في `config.js` كـ `emailDomain` (لازم قبل إنشاء أي مستخدمين).
